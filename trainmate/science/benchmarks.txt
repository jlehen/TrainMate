BENCHMARK (FITNESS TEST) GUIDELINES
===================================

AUTHORITY: MEASUREMENT. This file defines what a threshold anchor is and when a
test result can be trusted. Which blocks need which anchors, and how often the
plan's structure calls for one, is a plan document's decision.

A benchmark workout is a standardized, repeatable maximal or threshold effort
whose result establishes the athlete's THRESHOLD ANCHOR. All training zones and
session targets are derived as a percentage of that anchor. Keeping the anchor
current is what keeps every downstream zone/target accurate.

This is a sport-generic concept. The protocol and the unit of the anchor differ
by sport, but the pipeline is always the same:

   benchmark workout  ->  threshold anchor  ->  training zones / targets


1. WHEN TO RE-BENCHMARK
-----------------------
Re-anchor on EVIDENCE that the anchor is stale, not on a fixed calendar. A
formal test costs a quality session and a day of freshness, so the cheapest
correct answer is usually not to run one.

MODELLING FIRST. Where enough session data exists, the anchor can be modeled
from normal training — a cycling power-duration curve from interval work, an
estimated 1RM from rep-max sets — instead of a dedicated test. A plan that
already prescribes long efforts near threshold is generating this data for
free, so a modeled anchor tracks fitness continuously and costs nothing.
Prefer modeled estimates by default. Reserve formal tests for confirmation, for
anchors that cannot be modeled (1RM, 2k row), and for the trigger cases below.

Run a formal test when:
   - Sessions systematically decouple from target zones (planned efforts feel
     consistently too easy or too hard for their prescribed intensity). This is
     the primary trigger: it is direct evidence the anchor is wrong.
   - Returning from a detraining gap (illness, injury layoff, travel block),
     where the modeled anchor is stale and probably too high.
   - Entering a block whose targets DEPEND on that anchor, and no recent
     modeled estimate exists. Note that this is not every block transition —
     a block of all-out unpaced work needs no threshold anchor to prescribe it,
     so entering one triggers nothing.

MINIMUM INTERVAL. Do not run formal tests of the same anchor closer than about
3-4 weeks apart: below that the change is inside measurement noise, so the test
buys no information and costs real fatigue. This interval is a property of the
measurement and holds regardless of how short the plan's blocks are — a plan
with two-week blocks does not get a test at every boundary.

TEST FRESH, BUT NOT DURING A TAPER. An anchor set from a fatigued test
mis-scales every subsequent workout, so tests need a fresh day (positive or
neutral TSB, good recovery metrics). That does NOT mean putting the test in a
taper or deload week: a maximal effort is exactly the stress the taper exists to
remove, and spending it there defeats the taper's purpose. The taper PRODUCES
the freshness; spend it on an early, fresh day of the block that follows.


2. BENCHMARK PROTOCOL AND ANCHOR BY SPORT
-----------------------------------------
   Cycling:
     - Protocol: 20-min maximal steady effort (FTP = avg power x 0.95), or a
       ramp test.
     - Anchor: FTP (power). Zones = % of FTP.

   Running:
     - Protocol: 30-min time trial (avg pace/HR of last 20 min ~= threshold),
       Critical Speed test, or a 5k time trial.
     - Anchor: Threshold pace / Critical Speed. Zones = % of threshold pace
       (or pace bands).

   Swimming:
     - Protocol: Critical Swim Speed test (e.g. 400m + 200m time trials).
     - Anchor: CSS (pace per 100m). Zones = offsets from CSS pace.

   Rowing:
     - Protocol: 2k test, or 30-min test.
     - Anchor: Threshold pace/power. Zones = % of threshold.

   Strength:
     - Protocol: 1RM test, or estimated 1RM (e1RM) from a reps-to-near-failure
       or velocity-based set (safer, lower fatigue).
     - Anchor: 1RM (load). Working loads = % of 1RM.

   General aerobic (fallback):
     - Protocol: Cooper test / maximal aerobic speed or power test.
     - Anchor: MAS / MAP / VO2max proxy.


3. COACHING DIRECTIVES
----------------------
   - Treat the threshold anchor as the single source of truth for zone
     derivation; when a benchmark updates it, recompute all dependent zones.
   - Keep the benchmark protocol and conditions consistent run-to-run so results
     are comparable over time.
   - Adapt cadence to test cost: passively-estimated anchors (e.g. FTP) can
     update often and cheaply; fatiguing maximal tests (1RM, 2k row) warrant the
     §1 minimum interval and a rested day.
   - A rising anchor confirms progressive overload is working; a stalled or
     falling anchor across blocks signals plateau or under-recovery.
